# Стратегия тестирования

Тестов ровно столько, сколько нужно, чтобы (1) методика была доказуемо верной и
(2) демонстрация не сломалась. Всё остальное — трата времени, которого у нас нет.

## 1. Что тестируем обязательно

| Уровень | Что покрываем | Где |
| :--- | :--- | :--- |
| **Unit (обязательно)** | Всё в `src/core/`: предикаты D1–D10, индекс активности, прогресс, SPI, прогноз, привязка к зоне, статус техники, дедупликация по сессии, CPM, парсер справочника, парсер времени из EXIF/имени файла | `services/*/tests/unit/` |
| **API (обязательно)** | Хотя бы один тест на эндпоинт: код ответа, форма тела, конверт ошибки | `services/*/tests/api/` |
| **Контрактные** | Снапшот OpenAPI совпадает с кодом; ответы ключевых межсервисных эндпоинтов валидны по схеме | `make contracts` + `tests/contract/` |
| **E2E (один)** | Полный сценарий на поднятом стеке: объект → план → снимки → анализ → ожидаемые отклонения → отчёт | `scripts/e2e.sh` |
| **Качество CV** | precision / recall / mAP50 по классам на собственном тестовом наборе | `ml/eval/`, результат — в `docs/` |

## 2. Чего НЕ делаем

- Не тестируем фреймворк: что FastAPI валидирует `int`, что SQLAlchemy сохраняет строку.
- Не гоняемся за процентом покрытия. Важно покрытие `core/`, а не общее число.
- Не пишем моков на свои же чистые функции.
- Не тестируем вёрстку. Фронтенд проверяется руками по чек-листу демо.

## 3. Как писать тесты методики

Тест правила — это **зафиксированная договорённость о том, как система понимает стройку**.
Поэтому он оформляется как сценарий на русском, а не как «проверка функции».

```python
def test_d2_неполный_комплект_при_отсутствии_самосвалов():
    """Экскаватор есть, самосвалов нет при норме 2 → D2 средней серьёзности.

    Соответствует ТЗ, п.5.3, и демонстрационному дню 1.
    """
```

Требования к тестам `core/`:

- вход собирается фабриками из `tests/factories.py`, а не копипастой словарей;
- проверяется не только факт срабатывания, но и **содержимое `facts`**: именно оно
  попадает в объяснение пользователю;
- на каждый предикат — минимум три случая: срабатывает, не срабатывает, граница
  (ровно `min_sessions`, ровно порог, слепая зона, нерабочее время);
- отдельный тест-инвариант: **ни одно отклонение не создаётся без `facts` и `evidence`**;
- отдельный тест-инвариант: **по слепой зоне не создаётся ничего, кроме D10**.

## 4. Тестовые данные

| Набор | Где | Для чего |
| :--- | :--- | :--- |
| Фикстуры сессий и планов | `services/*/tests/fixtures/` | Unit-тесты методики, без снимков и БД |
| Демо-объект и хронология снимков | `data/seed/` | `make seed`, e2e, демонстрация |
| Собственный тестовый набор кадров | `ml/datasets/lct-test/` | Метрики CV: день/ночь/сумерки, лето/зима/дождь, перекрытия, разные стадии |

Демо-данные содержат **заранее заложенные отклонения** (D2, D3, D4, D10) — e2e проверяет,
что система нашла именно их. Если сценарий демонстрации меняется, тест меняется вместе с ним.

## 5. Тесты с базой

- Реальный PostgreSQL в docker, отдельная база `*_test`.
- Каждый тест — в транзакции с откатом; общего состояния между тестами нет.
- Миграции применяются один раз на сессию pytest: это заодно проверяет, что они рабочие.
- `downgrade` последней миграции проверяется отдельным тестом — иначе откат обнаружится
  в худший момент.

## 6. Внешние зависимости в тестах

- `vision-service`, `pos-engine`, LLM — заглушаются на уровне `clients/` (подменой класса
  клиента, не monkeypatch-ем httpx).
- Заглушка возвращает те же Pydantic-модели, что и настоящий клиент: расхождение
  поймается контрактным тестом, а не в проде.
- Реальные вызовы — только в e2e.

## 7. Метрики CV

Считаются скриптом `ml/eval/evaluate.py` на собственном тестовом наборе и оформляются
таблицей в документации:

| Класс | Изображений | Precision | Recall | mAP50 |
| :--- | :--- | :--- | :--- | :--- |
| … | … | … | … | … |

Правила: указываем размер выборки и условия съёмки; не показываем метрики на обучающей
выборке; **не придумываем числа** — если метрика не измерена, пишем «не измерено».
Матрица ошибок прикладывается отдельно: она объясняет, какие классы система путает,
и это честный ответ на вопрос жюри об устойчивости.
