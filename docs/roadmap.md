## 4. Контракты, которые фиксируются в первую очередь

Чтобы четыре трека шли параллельно, эти контракты описываются **17–18.09**, до реализации,
и дальше меняются только через ADR:

1. `GET /api/v1/plan/objects/{id}/stages?active_on=` — план на дату с правилами
   ([api-guidelines.md, п. 11.1](api-guidelines.md#111-план-на-дату--get-apiv1planobjectsidstagesactive_on2026-10-20));
2. `GET /api/v1/site/sessions/{id}/facts` — факт сессии
   ([п. 11.2](api-guidelines.md#112-факт-по-сессии--get-apiv1sitesessionsidfacts));
3. `POST /api/v1/vision/analyze` — детекции + стадия + качество кадра;
4. `POST /api/v1/analysis/runs` и форма объекта `deviation`;
5. `POST /api/v1/pos/generate` — уже зафиксирован в `services/pos-engine/README.md`.

Пока поставщик не готов, потребитель работает на фикстурах из `tests/fixtures/`,
совпадающих по форме с контрактом. Это и есть способ не ждать друг друга.

## 5. Риски и реакция

| Риск | Вероятность | Реакция |
| :--- | :--- | :--- |
| Не хватает размеченных данных по башенным кранам и бетононасосам | Высокая | Zero-shot детектор с текстовыми промптами работает без разметки; в крайнем случае класс помечается «низкая уверенность» и не участвует в `required` |
| LLM недоступна из-за сети или блокировок | Средняя | Провайдера проверяем с демо-машины заранее; отчёт формируется до показа и лежит в MinIO; `LLM_ENABLED=false` переводит резюме на шаблон |
| На демо-ноутбуке не проброшена карта в Docker | Средняя | `nvidia-container-toolkit` ставим и проверяем 20.09, а не 27-го; запасной путь — `VISION_DEVICE=cpu` |
| Дообучение не успевает | Средняя | Дефолт — open-vocabulary детектор, обучение ему не нужно. Дообучение переведено в разряд улучшений и может быть выброшено целиком |
| Нет времени на снимках | Высокая | Три источника: EXIF → имя файла → ручной ввод; статус `NEEDS_TIME` вместо потери снимка |
| «Работает/простой» ненадёжен | Высокая | Решение по серии сессий, статус `UNKNOWN`, ограничение зафиксировано в документации |
| Один трек отстаёт и блокирует остальные | Средняя | Фикстуры по контрактам с 18.09; никто не ждёт чужого сервиса |
| Интеграция «в последний день» | Высокая, классическая | T0 к 20.09 — интеграция происходит в начале, а не в конце |
| Демо ломается на чужой машине | Средняя | 27.09 полный прогон `make reset && make up && make demo` с нуля + записанное видео как страховка |

## 6. Что не делаем, даже если останется время

Соблазны, которые убивают хакатонные проекты. Зафиксировано, чтобы не спорить в процессе:

- трекинг конкретных машин, видеопоток, распознавание номеров;
- детекция подвоза материалов и внутренних работ;
- собственная система пользователей и ролей;
- Kubernetes, брокер сообщений, мультиарендность;
- переписывание уже работающего сервиса «красивее».

Свободное время идёт в: качество объяснений, демо-данные, метрики, документацию и репетицию
питча. Это ровно те критерии, по которым нас оценивают.
