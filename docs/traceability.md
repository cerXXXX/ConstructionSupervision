# Матрица соответствия требованиям ТЗ

Заполняется по мере реализации. Столбец «Статус»: `—` не начато, `~` в работе, `✓` готово
и проверено на демо-данных, `частично` — сделано с оговоркой в примечании. Обновляется
**в том же коммите**, что и код.

Статус `~` у F1: пакетная загрузка и импорт папки с временем из EXIF и имени файла, камерой
из подпапки и частичным успехом, просмотр снимков и ручной ввод времени через API готовы
(T23); экрана загрузки в интерфейсе ещё нет — T39.

Статус `~` у F2 и F6: `POST /api/v1/vision/analyze` распознаёт технику (YOLO-World, классы из
`equipment_classes.yaml`) и стадию (OpenCLIP zero-shot) на GPU и CPU (T24). Детектор дообучен
на датасете Лимы (T41): mAP50 на отложенном тесте 0,77 против 0,07 у zero-shot
([metrics.md](metrics.md)). Метрик на снимках организаторов ещё нет — T36 после H5. С T25 распознавание встроено в конвейер site:
site-worker сам распознаёт загруженные снимки, привязывает рамки к зонам (F3), считает
смещение (F4, наблюдение) и видимость участков (F5) и шлёт сигнал в analysis.

Статус `~` у F3: привязка по точке контакта, камеры, зоны, участки и импорт разметки готовы
и покрыты тестами (T22), детекции привязываются в конвейере (T25). С T26a факты окон уходят
в analysis по контракту «факты за период» (`GET /site/objects/{id}/facts`), и прогон анализа
в стеке доходит до `DONE`. С T26b правка зон пересчитывает факты окон без повторного
распознавания (задача `reapply_zones`), `POST /site/images/reanalyze` распознаёт снимки
заново — серверная часть F11 для зон готова. С T33 и T40 зоны и рамки видны на экране камер,
а полигоны правятся в редакторе зон интерфейса (`/objects/:id/settings/zones`) с пересчётом
фактов без повторного распознавания.

Оговорка по F10: лента предупреждений с карточкой отклонения — числа из `facts`, правило,
снимок с рамками, проверенные сессии, вердикт оператора — готова (T30,
`/objects/:id/deviations`). Гант план-факт готов (T32a, `/objects/:id/gantt`): плановые окна,
прогресс, фактический старт, прогноз, критический путь, связи. Загрузки техники на экране и
PDF (T34) ещё нет.

Оговорка по F11: зоны (T40) и правила «веха → техника» (T31, `/objects/:id/settings/rules`)
правятся в интерфейсе с пересчётом ленты; даты графика — пока через API, Гант с правкой дат —
T32. До него статус F11 — «частично».

## Нефункциональные требования (ТЗ, п. 4)

| Требование | Как обеспечивается | Замер | Статус |
| :--- | :--- | :--- | :---: |
| Снимок ≤ 1–2 с на CPU | `VISION_DEVICE=cpu`, вход 960 | не измерено | — |
| Снимок ≤ 100 мс на GPU | `VISION_DEVICE=cuda`, YOLO-World `s` | не измерено | — |
| Предупреждение ≤ 30 мин после снимков | Факт окна пересчитывается после каждого снимка, сигнал сразу запускает прогон | не измерено | — |
| Запуск одной командой | `docker compose up -d` | — | — |
| Конфигурация классов, правил и зон — в данных | `equipment_classes.yaml`, `stage_rule`, `deviation_rule`, полигоны зон | — | — |

| Код | Отклонение | Предикат | Статус |

Статус `✓` у D1–D4 и D10: сервис находит их на демо-данных в свои дни, `python scripts/e2e.py`
сверяет ленту со сценарием `data/seed/expected.json` (T28), карточка с числами, правилом и
снимком — на экране предупреждений (T30). Статус `~` у D5–D9: предикаты покрыты unit-тестами
на фикстурах, но в демо-сценарии их нет.

## Критерии оценки (ТЗ, п. 8)

| Критерий | Чем закрываем | Где показываем на демо |
| :--- | :--- | :--- |
| Логика сопоставления и объяснимость | Методика D1–D10, `facts` + `evidence` у каждого отклонения, эндпоинт `/explain` | Карточка отклонения, шаг 2 демо |
| Полнота функций п. 2 | Матрица F1–F15 выше | Прохождение всех экранов |
| Архитектура (расширяемость без кода) | Настройка данными, таблица в `architecture.md`, п. 9 | Правка правила в UI → пересчёт, последний шаг демо; добавление класса в YAML |
| Качество кода и документации | `AGENTS.md`, `code-style.md`, ADR, README каждого сервиса, тесты `core/` | Репозиторий и Swagger |
| Качество распознавания | Собственный тестовый набор, метрики по классам, матрица ошибок | Слайд с метриками |
| Скорость | Нефункциональные требования выше | Время обработки пакета на демо |
| UX | Экраны с состояниями загрузки, пустоты и ошибки, снимки с рамками | Весь показ |
| Питч | Слайды 7–11 шаблона + архитектура, обоснование стека, масштабирование | Презентация |
