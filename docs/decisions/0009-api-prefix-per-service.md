# ADR-0009. Префикс сервиса в пути API

**Статус:** принято, 17.09.2026

## Контекст

Семь сервисов за одним gateway. Нужно решить, как маршрутизировать: по имени ресурса
(`/api/v1/objects` → plan) или по префиксу сервиса (`/api/v1/plan/objects`).

## Решение

Путь всегда `/api/v1/<service>/<resource>`, и он **одинаков снаружи и внутри контейнера**:
gateway проксирует без переписывания, сервис монтирует роутер по тому же префиксу.

## Последствия

**Хорошо:** маршрут в nginx — семь строк, новые ресурсы не требуют правки gateway.
Отладка «напрямую в сервис» и «через прокси» дают идентичные пути — исчезает целый класс
ошибок. По URL в логе сразу видно, чей это запрос. Swagger каждого сервиса совпадает
с продуктовыми путями.

**Плохо:** путь на один сегмент длиннее, и в нём видна внутренняя структура системы.
Для модуля, встраиваемого в ИС заказчика, это скорее плюс: интегратор видит, к какой
подсистеме обращается.

## Альтернативы

- **Маршрутизация по ресурсу.** Красивее для внешнего потребителя, но требует правки
  конфигурации gateway при каждом новом ресурсе и создаёт риск коллизии имён между сервисами.
- **Переписывание путей в gateway (`rewrite`).** Внутренние и внешние пути расходятся,
  Swagger сервиса перестаёт соответствовать реальности.
- **Отдельный поддомен на сервис.** Требует DNS и сертификатов; для демо и для установки
  у заказчика — лишняя зависимость.
