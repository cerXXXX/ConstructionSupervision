# scripts — служебные скрипты

Всё, что вызывается из `Makefile`. Скрипт делает одно понятное действие и печатает,
что он сделал.

| Скрипт | Что делает | Готов |
| :--- | :--- | :--- |
| `openapi_dump.py` | Снимает OpenAPI сервиса импортом приложения, без докера и БД; используется в CI | да |
| `fetch_models.sh` | Скачивание весов детектора и классификатора стадии в `data/models/` | заглушка |
| `seed.sh` | Демо-данные: объект, генерация графика через `pos-engine`, камеры, зоны, загрузка снимков хронологии, прогон анализа | заглушка |
| `demo.sh` | Проигрывание демо-сценария: три «дня» объекта с заложенными отклонениями, с паузами для показа | заглушка |
| `contracts.sh` | Снятие снапшотов OpenAPI и генерация TS-клиента | заглушка |
| `e2e.sh` | Сквозной сценарий на поднятом стеке с проверкой ожидаемых отклонений | заглушка |
| `backup.sh` | Дамп трёх баз и зеркало бакетов MinIO | заглушка |
| `_not_implemented.sh` | Общая заглушка: печатает, чей это скрипт и что он должен делать, и возвращает 1 | да |

«Заглушка» значит, что файл есть и `make` его находит, но внутри — вызов
`_not_implemented.sh` с именем владельца из [docs/roadmap.md](../docs/roadmap.md).
Честное сообщение лучше, чем `No such file or directory`, а задача остаётся видимой
в [docs/board.md](../docs/board.md).

Отдельных `bootstrap.sh`, `health.sh` и `reset.sh` нет и не будет: `.env` создаёт сам
`Makefile`, базы и роли — скрипт инициализации Postgres (`infra/postgres/init/`),
а `make health` и `make reset` реализованы прямо в `Makefile` — оборачивать две строки
в файл незачем.

## Правила

- Скрипты идемпотентны: повторный запуск не ломает состояние.
- Никакой бизнес-логики: скрипт вызывает API сервисов, а не лезет в их базы напрямую.
  Единственное исключение — `bootstrap.sh` и `reset.sh`, которые работают с инфраструктурой.
- Все адреса и ключи берутся из `.env`, ничего не зашито.
- Скрипт, который что-то удаляет, спрашивает подтверждение либо требует флаг `--yes`.
